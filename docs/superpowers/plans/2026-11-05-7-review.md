# Step 7 — Review and human in the loop — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After the auto-fill, the user sees doubts first, then empty fields, settles each one (keep, choose, enter, leave empty), and the export warns only about what nobody settled.

**Architecture:** "Settled" = `answer.resolved_by = user` (the existing PATCH). The back adds `answer.proposed_value`, an `open` count, an export summary split into unsettled empty fields / unsettled doubts, and the `ready` status. The front groups the review queue with a pure `review.ts` and adds per-type actions; the export dialog gets two banners with *Back to review*.

**Tech Stack:** FastAPI, SQLAlchemy 2.1 + Alembic, pytest · Next.js 16, React 19, TanStack Query, next-intl, Vitest + MSW, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-05-7-review-design.md`

## Global Constraints

- Group order: **To check** → **No value** → **Filled automatically** (collapsed).
- `Leave empty` exists for every empty field, Yes/No included.
- Export is never blocked; it warns only about unsettled empty fields and unsettled doubts.
- No "AI" word in the interface; every text through next-intl (`frontend-i18n` skill); dates via `shared/utils/date.ts`.
- Screen tests follow the `screen-tests` skill; data calls follow `frontend-data-layer`; components follow `frontend-code-style`.
- Back: `make lint`, `make typecheck`, `make db-schema` after a model change, `make gen-api` after an API change.

## Review Focus

1. A doubt kept while the auto-fill is still running: PATCH wins over the later AI answer (already true; the kept answer must stay *Kept by you*, i.e. `proposed_value` not overwritten by the user's PATCH) — test in Task 1.
2. `Leave empty` on a field that has a value is not offered; clearing the text of a filled field is still "Entered by you" with value null → shows *Left empty by you* — accepted, test in Task 4.
3. Discard after everything was settled: status back to `not_started`, `open` = all fields — test in Task 2.
4. A conflict where the user picks the second candidate: *Kept by you*, no longer a doubt in the export — test in Task 3 and Task 5.
5. Pressing Enter on a settled card or on the last open field: no crash, selection stays — test in Task 4 (`nextOpen` returns null).

### Task 4: Pure review logic (front)

**Files:**
- Create: `frontend/src/features/review-queue/review.ts`, `review.test.ts`
- Modify: `frontend/src/features/review-queue/FieldList.tsx` (`QueueField` + `proposedValue: string | null`), `frontend/src/features/review-queue/index.ts`, `frontend/src/screens/live-fill/LiveFillScreen.tsx` (map `proposed_value`)

**Interfaces:**
- Produces:
  - `type ReviewGroup = "toCheck" | "noValue" | "automatic"`
  - `reviewGroup(field: QueueField): ReviewGroup | null` — null for a signature. Decided by the AI type only, which a user's save keeps, so a field never changes group when settled: `conflict | outdated | unsure` → toCheck; `manual` with `proposedValue` → toCheck; `auto | declaration` → automatic; anything else (missing, manual without suggestion, no AI answer) → noValue.
  - `isOpen(field: QueueField): boolean` — fillable, `resolvedBy !== "user"`, and (group toCheck, or no value).
  - `settledAs(field: QueueField): "kept" | "leftEmpty" | "entered" | null` — null unless `resolvedBy === "user"`; value null → leftEmpty; value equals `proposedValue` or any candidate value → kept; else entered.
  - `groupFields(fields: QueueField[]): { groups: { group: ReviewGroup; fields: QueueField[]; open: number }[]; signatures: QueueField[] }` — always the three groups in order (empty groups kept, so pills show 0), form order inside a group; signatures listed after the groups, as today ("Sign by hand").
  - `nextOpen(fields: QueueField[], afterId: number): number | null` — the next open field in queue order (groups order), wrapping to the first open one; null when none is open or only `afterId` is.

Behaviour (copy in `en.json`, key names free):
- Group headings: "To check", "No value", "Filled automatically"; the last collapsed: "{count} answers sourced from your documents, already in the form" + `Show` / `Hide`.
- Pills above the list: `To check · n`, `No value · n`, `Automatic · n` (n = open count, total for Automatic); `aria-pressed`; one active at a time, clicking it again shows all.
- Header (after the fill): "{count} fields need a look" from `counts.open`; 0 → "Everything is reviewed". Replaces `fieldsToFill` / `allFilled`.
- Selected open card actions:
  - conflict: radio group of candidates (value + source name + page + date when known; the first marked "most recent" when it has a `source_date`) and an "Enter another value" radio revealing the input → button `Use this one` (saves the chosen value);
  - outdated / unsure / manual with value: `Keep this value` (saves the current value) and `Enter new value` (focuses the input);
  - no value: input or Yes/No as today, plus `Leave empty` (saves null).
- Settled card: compact, ✓, status line "Kept by you · {time}" / "Left empty by you · {time}" / "Entered by you · {time}" (existing); still editable when selected.
- Non-selected cards: one line (label, value or "Empty", status).
